# 실험 기록

모든 학습·평가 실행을 **실패한 것까지** 기록한다 (Project_Rule.md 8절).
실행 폴더의 `run_meta.json`에 커밋, 설정, 데이터 버전, 환경, 상태(running / finished / failed)가 자동으로 남으므로 그 값을 옮겨 적는다.

## 기록 절차

```bash
python -m src.train.train --config configs/<설정>.yaml [--data <data.yaml>]          # 1. 학습
python -m src.train.evaluate --weights runs/train/<실행폴더>/weights/best.pt \
       --data <data.yaml> --split test                                               # 2. 평가 → eval_test.json
python -m src.train.summarize runs/train/<실행폴더>                                  # 3. 요약 표 출력
```

3번 출력을 아래 양식의 결과 칸에 붙이고, 해석과 다음 할 일을 직접 적은 뒤 `docs(train):` 커밋으로 남긴다.
학습 중에는 데이터 폴더를 옮기거나 이름을 바꾸지 않는다.

## EXP-001 Roboflow 1클래스 시험 학습 (2026-11-18)

| 항목 | 내용 |
|---|---|
| 날짜 / 브랜치 / 커밋 | 2026-11-18 / `exp/rf-single-class` / a8ff54c |
| 목적 | 실제 데이터에서 학습 파이프라인, 노트북 속도, 수렴 여부 확인 (프로젝트 모델 아님) |
| 설정 파일 | `configs/train_rf_trial.yaml` (yolo26n.pt, 3 epoch, imgsz 640, batch 4, flipud 0, seed 0) |
| 데이터 | Roboflow electric scooters images v10 (CC BY 4.0), 클래스 `e-scooters rider` 1개(킥보드+탑승자 묶음 박스). Roboflow 원래 분할 그대로 사용. 아래 '학습 데이터 구성' 참고 |
| 컴퓨터 | 이유섭 노트북, MX450 2GB, torch 2.14.1+cu126, Ultralytics 8.4.210 |
| 속도 | 3 epoch 13.3분 (epoch당 약 4~5분). 같은 시간에 다른 학습이 함께 실행 중이어서 Ultralytics가 이미지 읽기 속도 저하(약 6MB/s)를 경고했다. 단독 실행 속도는 별도로 측정해야 한다 |
| 결과 (val) | epoch 1→3: mAP50 0.696 → 0.837 → 0.857, mAP50-95 0.337 → 0.605 → 0.661, Recall 0.914 |
| 결과 (test, best.pt) | P 0.880, R 0.901, mAP50 0.927, mAP50-95 0.711 |
| 해석 | 메모리 부족 없이 학습·검증·저장이 끝까지 돌았고, 손실이 줄고 mAP가 올라 정상적으로 수렴한다. 다만 (1) 묶음 박스라 사람 수를 셀 수 없어 다중 탑승 판정에 쓸 수 없고, (2) 파일 이름으로 보아 영상 프레임을 Roboflow가 프레임 단위로 분할했을 가능성이 있어 test 점수가 부풀려졌을 수 있다. 점수는 성능 근거로 쓰지 않는다. |
| 다음 할 일 | 학습 곡선이 평평해지는 지점 확인(아래 10 epoch 실행 참고). 2클래스 데이터(v0)가 오면 정식 1차 학습 |

**10 epoch 실행 (같은 날, `--epochs 10`, 실행 폴더 `20261118-1602_rf-trial_dsrf-escooter-v10_640`)**

| epoch | Precision | Recall | mAP50 | mAP50-95 |
|---|---|---|---|---|
| 1 | 0.756 | 0.805 | 0.815 | 0.553 |
| 2 | 0.742 | 0.850 | 0.809 | 0.528 |
| 3 | 0.781 | 0.866 | 0.843 | 0.586 |
| 4 | 0.850 | 0.862 | 0.857 | 0.643 |
| 5 | 0.819 | 0.879 | 0.858 | 0.633 |
| 6 | 0.852 | 0.917 | 0.876 | 0.701 |

- **실패:** 7번째 epoch 도중 `Image Not Found`로 중단되었다. 학습 중에 데이터 폴더를 `project_data/robotflow/raw/`로 재정리하면서 학습이 읽던 경로가 사라졌기 때문이다. 6 epoch까지의 가중치(best.pt, last.pt)는 남았다. 실행 기록 `run_meta.json`은 학습이 끝나야 쓰이므로 이 실행에는 없다.
- **test (6 epoch best.pt, 새 경로 `raw/data.yaml`로 평가):** P 0.902, R 0.924, mAP50 0.929, mAP50-95 0.737
- **해석:** 6 epoch에서도 mAP50-95가 0.633 → 0.701로 오르고 있어 아직 평평해지지 않았다. 학습 곡선의 끝을 보려면 더 긴 학습이 필요하다(4070 PC에서 epochs 100, patience 20 권장).
- **교훈:** 학습 중에는 데이터 폴더를 옮기거나 이름을 바꾸지 않는다. 데이터 정리는 학습 전후에 한다.
- 참고: `robotflow/지쿠터단일추적/scooter_only`는 같은 v10 데이터에서 박스 없는 이미지만 뺀 사본이다(train 2,119 / valid 552 / test 297, 박스 수와 클래스는 동일). 킥보드만 감싼 새 데이터가 아니다.

**학습 데이터 구성** (라벨 파일을 직접 세어 확인, 2026-11-18)

| 분할 | 이미지 | 박스 | 박스 없는 이미지 | 이미지당 박스 수 (0 / 1 / 2 / 3 / 4개) |
|---|---|---|---|---|
| train | 2,506 | 2,491 | 387 | 387 / 1,762 / 344 / 11 / 2 |
| valid | 726 | 672 | 174 | 174 / 440 / 105 / 6 / 1 |
| test | 368 | 358 | 71 | 71 / 240 / 54 / 2 / 1 |

- 모든 라벨이 bbox 형식(5개 값)이며 클래스 번호는 0 하나뿐이다.
- 박스 범위: 샘플 12장을 그려 본 결과 모두 킥보드와 탑승자를 함께 감쌌다. Project_Rule.md 6.3절에 따라 2클래스 학습에는 이미지만 쓰고 박스는 다시 만들어야 한다.
- 전처리: 모든 이미지를 1280×1280으로 늘림(비율 왜곡), 증강 없음.
- 자동 재라벨링 시도(COCO yolo26n/yolo26x로 person, 비슷한 클래스와 규칙으로 kickboard)는 5장 중 사람 누락이 많고(2인 탑승 장면의 뒷사람 포함) 킥보드 박스가 부정확해 학습 라벨로 쓸 수 없었다. 사람 검수를 전제로 한 초안 생성까지만 가능하다.
