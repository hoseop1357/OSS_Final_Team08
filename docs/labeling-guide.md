# 라벨링 기준서 (Labeling Guide)

> 담당: 최민규 (데이터) · 필수 리뷰: 이시준 (연관 로직) · 최종 수정: 2026-11-25 · 상태: 초안

1단계(다중 탑승 판정) 탐지 데이터의 라벨링 기준이다. AI Hub, Roboflow, 직접 촬영 데이터에 똑같이 적용한다.
이 기준의 **사람 박스 하단 = 발 위치** 정의는 `src/logic/association.py`의 연관 로직 입력이므로, 바꿀 때는 이시준과 함께 바꾼다.

## 1. 클래스

| ID | 이름 | 정의 |
| --- | --- | --- |
| 0 | `kickboard` | 서서 타는 전동 킥보드 **본체만** (발판, 바퀴, 지지대, 손잡이 포함) |
| 1 | `person` | 사람 한 명의 **전신** (머리부터 발끝까지) |

- **탐지 라벨에는 탑승 여부를 담지 않는다.** 타고 있든 걷고 있든 사람은 `person`, 달리든 세워져 있든 킥보드는 `kickboard`다. 탑승 여부는 연관·판정 로직이 정한다(Project_Rule.md 9절).
- 헬멧 관련 클래스는 1단계에서 만들지 않는다. 2단계에서 사람 박스 상단을 잘라 쓰므로, 사람 박스에 **머리가 빠지지 않게** 그린다.
- 형식은 Ultralytics YOLO txt(`클래스 x중심 y중심 너비 높이`, 실제 이미지 크기로 0~1 정규화)다.

**`docs/scenarios.md`(발표 PPT 기준 4클래스)와의 대응**

| scenarios.md | 1단계 라벨 |
| --- | --- |
| Electric scooter | `kickboard` |
| Person | `person` |
| Helmet_on / Helmet_off | 1단계에서는 라벨링하지 않음 (2단계에서 `person` 박스 상단을 잘라 분류) |

## 2. `kickboard` 박스

- **킥보드만 감싼다.** 탑승자의 몸은 넣지 않는다. 탑승자 다리가 킥보드를 가려도, 킥보드가 있는 범위를 기준으로 그린다.
- **손잡이(핸들바)까지 포함한다.** 위쪽 끝은 손잡이 윗선, 아래쪽 끝은 바퀴가 땅에 닿는 선, 좌우는 앞바퀴·뒷바퀴·손잡이 끝이다.
- 손잡이가 탑승자 손이나 몸에 가려 보이지 않으면, 지지대(스템)의 방향으로 손잡이 높이를 추정해 포함한다.
- AI Hub 이미지는 PM 박스(킥보드+탑승자 묶음)를 위치 힌트로만 보고, 그 안에서 킥보드만 다시 그린다.

## 3. `person` 박스

- **박스 하단 = 발 위치.** 하단 선은 땅에 닿은 발(탑승 중이면 발판 위의 발)의 바닥에 맞춘다. 연관 로직은 이 하단 중앙점을 발 위치로 쓴다.
- 위쪽 끝은 머리 꼭대기(헬멧을 썼으면 헬멧 꼭대기), 좌우는 팔·다리를 포함한 몸 전체다.
- 손에 든 물건(가방, 우산)은 넣지 않는다. 몸에 붙은 배낭은 넣어도 된다.

### 3.1 가려진 사람 (가장 중요)

- **2인 탑승의 뒷사람처럼 가려진 사람도 반드시 라벨링한다.** 뒷사람 누락은 다중 탑승을 1인 탑승으로 바꾸는 가장 흔한 오류다(Project_Rule.md 6.4절).
- 가려진 사람은 **보이는 부분만이 아니라 가려진 몸까지 추정한 전신 박스**로 그린다. 특히 발이 가려져도 하단을 추정한 발 위치(보통 앞사람과 같은 발판 높이)까지 내린다.
  보이는 부분만 그리면 하단이 허리나 무릎에서 끝나 발 위치가 킥보드 밖으로 잡히고, 탑승자로 연결되지 않는다.
- 머리나 어깨가 보여 **한 사람으로 구분할 수 있으면** 라벨링한다. 팔이나 다리 일부만 보여 몇 명인지 알 수 없으면 라벨링하지 않는다.
- COCO 사전학습 모델의 자동 라벨은 보이는 부분만 감싸는 경우가 많다. 검수할 때 가려진 사람의 박스 하단을 위 기준대로 늘린다.

### 3.2 연관 로직과의 연결

이 기준서의 정의는 main에 병합된 연관 로직의 입력과 같아야 한다.

| 기준서 | 코드 (`src/logic/`) |
| --- | --- |
| 사람 박스 하단 중앙 = 발 위치 | `box_utils.foot_point()` |
| 킥보드 박스는 발판·바퀴·손잡이까지 | `box_utils.expand_for_foot()`가 좌우·하단만 넓히고 상단은 그대로 둠 |
| 가려진 뒷사람도 발까지 추정 | `configs/logic.yaml`의 `foot_margin_ratio`(0.10)로 앞뒤 발 위치 차이를 흡수 |

기준을 바꾸면 위 함수와 설정값도 함께 확인한다(필수 리뷰: 이시준).

## 4. 애매한 사례

| 사례 | 처리 |
| --- | --- |
| 세워 둔 킥보드, 주차된 킥보드 여러 대 | 각각 `kickboard` |
| 킥보드를 끌거나 밀며 걷는 사람 | 사람은 `person`, 킥보드는 `kickboard` (탑승 여부는 로직이 판단) |
| 접혀 있거나 들고 있는 킥보드 | 형태가 킥보드로 보이면 `kickboard` |
| 정지한 킥보드 옆에 서 있는 사람 | 각각 `person`, `kickboard` |
| 자전거, 오토바이, 좌석이 있는 전동 스쿠터, 유모차 | 라벨링하지 않음 (단, 그 위의 사람은 `person`) |
| 비전동 킥보드(어린이용 킥보드 등) | **팀 확인 필요.** 초안은 형태가 같으므로 `kickboard` |
| 이미지 가장자리에 잘린 객체 | 보이는 범위까지만 그린다 |
| 광고판·포스터 속 사람, 유리에 비친 사람, 마네킹 | 라벨링하지 않음 |
| 너무 작아 사람이 식별할 수 없는 객체 | 라벨링하지 않음. **최소 크기는 팀 확인 필요** (초안: 1920×1080 기준 박스 높이 15px 미만 제외) |
| 사람이 많이 겹친 군중 | 한 사람씩 구분되면 각각 그린다 |

## 5. 작업 도구와 기록

**검수 순서 (AI Hub, 배치 단위)**

1. `src.data.review_batch`로 배치를 고른다 (batch01: test 분할 150장 = 다중 탑승 96 + 1인 36 + 끌기 18).
2. `src.data.roboflow_autolabel`로 kickboard/person 초안을 만든다. 다중 탑승 후보·탑승자 미검출 이미지는 `review/`로 나뉜다.
3. 로컬 CVAT에 초안을 올려 이 기준서대로 고친다. `review/`는 전부, `auto/`도 전부 본다(평가 세트이므로).
4. 검수 결과를 `review_log.csv`(`data/README.md` 양식)에 남긴다.


- **AI Hub 이미지는 로컬 CVAT에서만** 라벨링·검수한다. 무료 Roboflow 프로젝트는 공개될 수 있어 재배포 금지에 걸린다(Project_Rule.md 6.3절).
- Roboflow 출처 이미지는 Roboflow에서 작업해도 된다. 내보낼 때는 증강 없는 버전을 쓴다.
- 자동 라벨은 검수 전에는 초안이다. 이미지마다 검수 여부를 기록하고, **검수하지 않은 자동 라벨은 평가 세트에 쓰지 않는다.**
  기록 위치와 형식은 `data/README.md`를 따른다.

## 6. 확인이 필요한 항목 (리뷰 때 결정)

- [ ] 가려진 사람의 전신 추정 박스 방식이 연관 로직(`foot_margin_ratio`)과 맞는지 (이시준)
- [ ] 비전동 킥보드를 `kickboard`에 넣을지
- [ ] 최소 박스 크기
- [ ] 킥보드 위의 아이(보호자와 함께 탄 아이)도 다중 탑승으로 볼지 → 라벨은 둘 다 `person`이고, 판정 기준은 로직 쪽에서 정한다
